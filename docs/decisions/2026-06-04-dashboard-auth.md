# ADR: Авторизация дашборда — пароль + сессия, HTTPS через nginx

**Status:** Accepted
**Date:** 2026-06-04
**Tags:** security, deployment

## Context

Дашборд (FastAPI) изначально слушал `0.0.0.0:8000` без какой-либо
авторизации — единственной защитой был HH OAuth внутри приложения, но сам
UI и все `/api/*` эндпоинты были открыты любому, кто получит доступ по сети.
Пользователь хочет управлять ботом и смотреть историю откликов **с телефона
через интернет**, то есть дашборд должен быть выставлен наружу.

Открытый дашборд в интернете недопустим: через него можно запускать отклики,
читать переписку, видеть HR-контакты и токены. Нужен барьер, работающий и в
Docker (за nginx), и при локальном запуске (`python web_app.py`).

Ограничения:
- Своего домена у пользователя нет — вход планируется по IP:порту.
- Валидный TLS-сертификат на голый IP не выписать (Let's Encrypt требует
  домен); в проекте уже есть self-signed `ssl/hh.crt` и nginx на 8443.
- Не плодить тяжёлых зависимостей.

## Decision

Защита в два слоя, на уровне приложения + транспорт:

1. **Авторизация (app-level).** Starlette `SessionMiddleware` (signed cookie,
   секрет из `SESSION_SECRET`) + HTTP-middleware `_require_auth` в
   `app/routes/__init__.py`. Пароль задаётся `DASHBOARD_PASSWORD`:
   - пусто → авторизация **выключена** (обратная совместимость, локальная
     разработка);
   - задан → все маршруты, `/` и WebSocket `/ws` требуют сессию; `/login`,
     `/logout`, `/static`, `/favicon.ico` — публичны; `/api/*` без сессии →
     401, страницы → редирект на `/login`.
   - Форма входа и проверка пароля (`secrets.compare_digest`) — в
     `app/routes/auth.py`. Сессия живёт 14 дней.
2. **Транспорт (HTTPS).** Существующий nginx терминирует TLS на 8443
   (self-signed), 8000 редиректит на HTTPS, проксирует на `hh-bot:8000`
   (добавлено проксирование WebSocket). Заход — `https://<IP>:8443`.

`.env` (с `DASHBOARD_PASSWORD`/`SESSION_SECRET`) добавлен в `.gitignore`;
`.env.example` — шаблон. `web_app.py` подгружает `.env` без внешних
зависимостей.

## Consequences

**Positive**
- Дашборд можно безопасно выставлять в интернет: чужой не пройдёт ни в UI,
  ни в `/api`, ни в `/ws`.
- Работает одинаково в Docker и при локальном запуске.
- Нулевая настройка для локалки (пустой пароль = старое поведение).

**Neutral**
- Добавлена зависимость `itsdangerous` (нужна `SessionMiddleware`).
- Появились `DASHBOARD_PASSWORD` и `SESSION_SECRET` в окружении; при смене
  `SESSION_SECRET` все сессии инвалидируются.

**Negative**
- Self-signed сертификат → браузер показывает предупреждение при первом
  заходе (принять один раз). Валидного TLS без домена нет.
- Один общий пароль, без ролей/пользователей — достаточно для одного
  владельца, но не для многопользовательского доступа.

## Alternatives considered

- **Tailscale / VPN.** Максимально безопасно (дашборд не виден в публичном
  интернете), но пользователь выбрал заход по IP:порту без доп. клиента.
- **nginx HTTP Basic Auth.** Проще, но защита только на nginx (не работает
  при локальном запуске без nginx) и без управляемой сессии/формы.
- **Cloudflare Tunnel + Access.** Даёт валидный сертификат и edge-авторизацию
  без своего домена; отложено как опциональный апгрейд — у пользователя есть
  аккаунт Cloudflare, переход возможен позже без правок кода.

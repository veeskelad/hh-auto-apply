# Дизайн-документ: Реструктуризация сайдбара и информационной архитектуры дашборда

**Дата:** 2026-06-02  
**Статус:** Согласовано с пользователем (Выбран вариант A)  

---

## 1. Цель реструктуризации

Существующая структура дашборда HH Auto Apply перегружена избыточными разделами в боковом меню. Пользователь вынужден переключаться между 11 разделами, многие из которых дублируют аналитическую информацию по откликам.

**Главный сценарий продукта:**
`Подключить HH` → `Настроить кампанию` → `Запустить автоотклики` → `Мониторить чаты` → `Отвечать по сценарию` → `Анализировать результат`.

Мы перерабатываем интерфейс под этот сценарий, сокращая сайдбар с 11 до 6 логичных разделов.

## 2. Согласованная структура меню (Вариант A)

1. **Обзор** (бывшая «Главная»):
   - Карточки аккаунтов со статусами работы, счетчиками и тумблерами.
   - Сводка сессии (найдено / отправлено / ждет ответа / ошибки).
   - Главные действия (запуск, пауза бота).

2. **Кампании** (бывший раздел «Кампании» / `apply`):
   - Конфигуратор автооткликов (поисковые запросы, регион, удаленка, лимиты, ключевые и стоп-слова).

3. **Чаты** (бывший раздел «AI Ответы» / `llm`):
   - Экран диалогов, истории переписки и ручного управления AI-ответами HR-менеджерам.
   - Статус-бар LLM.

4. **История** (объединение разделов: Отклики, Тесты, База, HH Статус, Просмотры):
   - Внутри раздела делаются аккуратные горизонтальные вкладки:
     - **Отклики** (бывшая панель `applied` + форма «Ручной отклик»).
     - **Тесты** (бывшая панель `tests`).
     - **База вакансий** (бывшая панель `db`).
     - **HH Статус** (бывшая панель `hh`).
     - **Аналитика просмотров** (бывшая панель `views`).

5. **Настройки** (бывший раздел `settings`):
   - Подключение браузерных сессий (пароль / куки).
   - Обновление кук аккаунтов.
   - Тонкие параметры бота (страниц на URL, задержки, паузы, лимиты).
   - Шаблоны писем и ответов на опросы.
   - AI / LLM настройки (API-ключи, базовые URL, системный промпт, профили моделей).

6. **Диагностика** (бывший раздел «Лог» / `log`):
   - Живой технический лог событий для мониторинга ошибок и отладки работы бота.

## 3. Логика генерации AI-сопроводительных писем

При генерации сопроводительного письма бот должен следовать строгому правилу:
- Генерировать релевантный опыт, исходя из требований описания вакансии и опыта, описанного в выбранном для кампании резюме.
- **Никогда не писать оправданий** (например: *«Я не работал с технологией X, но готов изучить»* или *«К сожалению, у меня нет опыта в Y»*).
- Акцентировать внимание на сильных и релевантных сторонах кандидата, описанных в его резюме.

## 4. План технической реализации

### Шаг 4.1: Меню в сайдбаре (`static/index.html`)
Обновить блок меню `<nav class="sidebar-nav" id="tabs">`:
- Оставить вкладки:
  - `auth` (показывается при клике на "Войти в HH" или в настройках, но теперь сессии лежат в Настройках).
  - `main` с текстом `📊 Обзор` (data-tab="main").
  - `apply` с текстом `🚀 Кампании` (data-tab="apply").
  - `llm` с текстом `💬 Чаты` (data-tab="llm").
  - `history` с текстом `📂 История` (data-tab="history") — **НОВЫЙ РАЗДЕЛ**.
  - `settings` с текстом `⚙️ Настройки` (data-tab="settings").
  - `log` с текстом `🛠 Диагностика` (data-tab="log").

### Шаг 4.2: Создание объединенной панели «История» (`static/index.html`)
1. Создать новую панель `<div id="panel-history" class="panel">`.
2. Внутри нее разместить горизонтальный переключатель вкладок (sub-tabs):
   - `Отклики` (показывает форму ручного отклика и таблицу откликов).
   - `Тесты`.
   - `База вакансий`.
   - `HH Статус`.
   - `Аналитика`.
3. Переместить разметку панелей `panel-applied`, `panel-tests`, `panel-db`, `panel-hh`, `panel-views` внутрь этой единой панели как подпанели (`sub-panel`), которые переключаются через JS.

### Шаг 4.3: Консолидация настроек (`static/index.html`)
Переместить форму подключения сессий (`panel-auth`) внутрь вкладки настроек (`settings-tab-connection`) в качестве первого подраздела. Вкладка авторизации `auth` больше не будет маячить в основном меню сайдбара, освобождая место. Авторизация — это разовое действие при настройке!

### Шаг 4.4: Адаптация JS-логики (`static/js/app_v6.js`)
1. Обновить функцию `switchTab`, чтобы при переключении на `history` автоматически активировалась первая горизонтальная вкладка (Отклики).
2. Написать простую функцию `switchHistoryTab(subTab)` для управления отображением подпанелей внутри раздела «История».
3. Проверить, что все селекторы и WebSocket-обновления корректно находят элементы на новых местах.
